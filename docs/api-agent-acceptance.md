# Web 0.8.0 API 排版验收

七篇真实学术稿件经 Codex API 与 DeepSeek API 分别调用 HTTP MCP 自动排版，最终 14 份校样均通过本次指定版式与技术检查。两种模型各生成 72 页。模型只提出工具调用，排版、版本检查、PDF 编译和机器预检由书页执行；排版过程不依赖 Computer Use。

## 验收口径

- 同篇使用相同规范化源文档及相同目标：210 × 285 mm 单栏、正文 10.5 pt、中英文主标题 18 / 12 pt、双语摘要 9 pt / 14 pt 行距、章节 11 pt、数据表和参考文献 8.5 pt、指定双面页眉及连续页码。
- 原 Word 文件 SHA-256 保持不变；修订采用最终显示版本。正文、公式、图片、注释、图表关系在 Agent 操作前后逐项保持。
- 检查实际 PDF 的标题字号、每页页码、页面尺寸、字体嵌入、公式覆盖、组件映射和页面越界；额外核验全部角色样式、数据表、章节及红橙 DOC 的 12 处学名、52 处斜体标记和公式编号。
- 684 个公式、55 个图像组件、8 条注释。六幅原 DOC 缺图由用户提供的已发表样本 PDF 恢复，保留来源页、裁切区域及摘要；没有合成或猜测图片。
- 样本页面为 216 × 303 mm，单双栏并存；本轮目标是单栏 210 × 285 mm，不能以相同页数或逐像素复制样本为验收条件。
- 第 4、5 篇在发现英文摘要行距遗漏或接口问题后，两模型成对重跑。每篇对照的源摘要和协议版本一致；不同稿件包含修复迭代。结果不是对所有模型任务的普遍排名。

## 软件回归

- 网站 / HTTP MCP：278 项通过。
- Python 排版引擎：139 项，137 项通过；本机不具备的 STIX 字体夹具和 LibreOffice Draw 集成环境各跳过 1 项。
- 原本地核心：92 项，90 项通过、2 项既有环境跳过。
- 独立服务器与网页框架构建通过。
- 浏览器验证模型选择、历史 API 任务、真实 PDF 报告、整次撤销与版本恢复，刷新后恢复版本仍保留。
- 真实连接器 CLI 经 HTTP/MCP 领取并完成模型请求的集成测试通过；连接器所有权、重复提交、离线、超时和停止路径有回归覆盖。
- Linux 服务器隔离环境对最终 14 份文档重新编译、校验 PDF，全部通过且页数与本机一致。上线后通过 HTTPS → 桌面连接器 → DeepSeek → MCP 再完成一篇 9 页全文校样，下载摘要一致，113 个工具可发现。
- 部署前备份配置和工程数据；切换后 39 个原有工程索引、112 个存储对象内容保持不变。线上额外验收消耗 105,765 tokens，不计入七稿配对对比。

## 交付边界

当前内置 API 循环用于已导入、首面角色已确认的单篇期刊稿。整期与 Word 导出仍可通过既有独立 MCP 工具调用。`review` 表示技术校样可供审阅，不是自动发印批准：原稿残留文字、刊期元数据、学术语义、图件原始清晰度、印厂 PDF/X 要求仍需确认。

Windows 的旧 DOC 转换需要本机 Microsoft Word。Linux 对可能丢失斜体文字的 WPS 二进制 DOC 明确拒绝无损承诺，要求先用 Word 转为 DOCX。私有网关依赖运行中的桌面连接器、Magpie 和其网络；接口连通性故障不会被标成排版成功。

使用与配置见 [API 排版指南](api-agent.md)。
